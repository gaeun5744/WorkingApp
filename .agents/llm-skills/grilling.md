# Grilling (구현 전 정렬 인터뷰)

계획이나 설계를 **구현 전에** 집요한 질문으로 stress-test 해서, 에이전트와 사용자가 같은 그림을 공유하도록 정렬합니다.
AI가 잘못된 결과물을 만드는 가장 큰 원인은 코딩 실력이 아니라 **정렬 실패(misalignment)** 입니다. 모호함을 코드로 굳히기 전에 질문으로 좁힙니다.

> 출처 개념: Matt Pocock의 grilling 방법론 (https://github.com/mattpocock/skills).

## 언제 쓰나

- 사용자가 "grill", "구워줘", "계획 검증해줘"처럼 명시적으로 요청할 때.
- 요구가 모호하거나, 되돌리기 어려운 결정(스키마, 공개 API, 의존성 추가, 아키텍처)이 걸린 작업을 시작하기 전.
- 작업 범위가 넓어 한 방향으로 조용히 해석하면 위험할 때.

작고 명확한 작업은 grilling 없이 바로 진행합니다. 과하게 캐묻지 않습니다.

## 핵심 규칙

1. **한 번에 한 질문**. 답을 받은 뒤 다음 질문으로 넘어갑니다. 질문을 한꺼번에 쏟아내지 않습니다.
2. **각 질문에 추천안을 함께** 제시합니다. 사용자가 동의/수정만 하면 되도록 "저는 A를 제안합니다. 이유는 …. 괜찮을까요?" 형태로 묻습니다.
3. **먼저 스스로 확인**합니다. 코드/문서(Read·Grep)로 답할 수 있는 것은 질문하지 않고 직접 찾습니다. 정말 사용자만 결정할 수 있는 것만 묻습니다.
4. **결정 트리를 의존 순서대로** 진행합니다. 앞 결정이 뒤 결정을 좌우하면 앞 것을 먼저 확정합니다.
5. **상호 이해가 될 때까지 반복**하고, 끝나면 합의된 계획을 짧게 요약해 확인받은 뒤 구현으로 넘어갑니다.

## 무엇을 grill 하나 (질문 우선순위)

- **범위 / 비범위**: 무엇을 하고, 무엇을 **안 하는가**.
- **모호한 요구 / 암묵적 가정**: 표현이 두 가지로 읽히는 지점.
- **엣지·실패 케이스**: 빈 결과, 네트워크 실패, 권한 거부, 잘못된 입력 등의 처리.
- **데이터 모델 / 계약**: API 응답 형태, 상태 모델, 경계 타입 선택지.
- **UX 분기**: loading / empty / error / disabled 등 어떤 상태를 보여줄지.
- **되돌리기 어려운 결정**: 영속 스키마, 공개 API 시그니처, 새 의존성/모듈.

## 안티패턴

- 질문 10개를 한 번에 나열하기.
- 추천안 없이 "어떻게 할까요?"만 던지기.
- 코드만 봐도 답이 나오는 것을 질문하기.
- 합의 없이 곧바로 구현을 시작하기.
- 사소한 것까지 끝없이 캐물어 진행을 막기.
