# 2주차 시나리오 확인 기록

## 시나리오 B. 인터넷이 끊겼다가 복구됐다 (2026-11-03)

환경: 에뮬레이터 Pixel 8 API 37, 시뮬레이션 센서(`-PfakeStepSensor=true`, 1초에 1걸음), Mock 서버(앱 내부 `MockApiInterceptor`)

### 전제: Mock 서버에서 "오프라인"이 의미하는 것

Mock 서버는 앱 안의 OkHttp Interceptor라 실제 네트워크를 쓰지 않는다. 그래서 비행기 모드에서도 HTTP 요청 자체는 실패하지 않는다.
오프라인의 효과는 **WorkManager의 `NetworkType.CONNECTED` 제약**으로만 나타난다. 이번 확인은 이 제약이 동기화를 막고, 복구 시 바로 풀어 주는지를 본다.
요청 도중 연결이 끊기는 경우(`IOException` → `AppError.Network` → `Result.retry()` + 지수 백오프)는 Mock으로 재현할 수 없어 실제 서버 전환(M11)에서 확인한다.

### 진행과 결과

| 시각 | 동작 | 관찰 (근거) |
|---|---|---|

### 결론

- 오프라인 동안 걸음은 Room에 계속 쌓이고, 동기화는 시도조차 하지 않는다 (배터리·요청 낭비 없음)
- 네트워크가 돌아오면 예정 시각이 지난 작업이 즉시 실행된다
- 오프라인이 길어 토큰이 만료돼도 401 → 갱신 → 재시도가 한 번의 작업 안에서 처리된다
- 업로드 중 바뀐 날짜는 미동기화로 남아 다음에 다시 보낸다. 같은 날짜를 다시 보내도 서버는 `max(기존, 새 값)`이라 결과가 같다 (멱등, `MockApiTest`로 검증)

### 확인하지 못한 것

- 요청 도중 연결 끊김과 지수 백오프 재시도 (Mock 한계, M11)
- 시뮬레이션 센서는 5초마다 걸음이 늘어 `synced=1`이 되는 순간을 기기에서 보지 못함. 걸음이 멈춘 상태의 표시 갱신은 계측 테스트(`StepRepositoryImplTest`)로 검증

## 시나리오 E. 자정을 넘긴다 (2026-11-14, Phase A 완료 기준)

환경: 에뮬레이터 Galaxy Z Flip6 API 34 (`google_apis`, root), 시뮬레이션 센서(`-PfakeStepSensor=true`, 1초에 1걸음), Mock 서버, 시간대 KST

### 진행 방법과 주의점

- 자동 시간을 끄고(`settings put global auto_time 0`) root `date`로 시계를 **23:50:00으로 먼저 맞춘 뒤** 앱을 처음 설치·실행했다.
- 앱 실행 후에 시계를 바꾸면 결과가 왜곡된다. `todayFlow()`는 다음 자정까지 `delay`(경과 시간 기준)로 기다리므로 벽시계를 옮겨도 깨어나는 시각은 그대로이고, 시뮬레이션 센서는 측정 시각을 벽시계로 찍어 가짜 측정 공백이 생긴다.
- 확인 도구: Room DB(`sqlite3`), `dumpsys notification`, `uiautomator dump`(홈 화면 숫자), `logcat`(OkHttp·WorkManager)

### 진행과 결과

| 시각 | 동작 | 관찰 (근거) |
|---|---|---|
| 23:50:20 | 설치 → 온보딩(닉네임, 역삼동) | `POST /auth/anonymous` 201, `PUT /me/region` 200. 온보딩 직후 동기화는 걸음이 없어 요청 없음 |
| 23:50:57 | 자정 전 상태 | `daily_steps` 11-14 = 53 (`synced=0`), `hourly` 11-14 23시 = 53, 알림 "오늘 53걸음", 홈 53 |

### 결론

- 걸음은 측정 시각의 날짜·시간대로 나뉜다. 자정 리셋 코드 없이 23:59:58까지는 전날, 00:00 이후는 새 날짜에 쌓였다.
- 홈 화면과 알림은 자정 + 1초에 새 날짜로 바뀐다.
- 전날 미동기화 행은 자정 이후 첫 동기화에 함께 올라간다(최근 7일 창, W2-Q3).

### 확인하지 못한 것

- 실제 시계가 흐르는 실기기(삼성)에서 자정을 넘기는 경우. 하드웨어 센서는 걸음마다 이벤트를 보내지만 화면이 꺼진 동안은 15분 스냅샷 워커에 의존하므로, 자정 직전 걸음이 다음 날로 넘어가는 오차(`StepDeltaCalculator` 알려진 한계)는 이번 확인에 나타나지 않았다.
- `StepSnapshotWorker` 단독 측정(서비스가 죽은 상태)으로 자정을 넘기는 경우.
